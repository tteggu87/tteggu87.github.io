# I03 / I04 시각 리뷰

판정: **전체 FAIL — 최종 원본 검증 미완료**. 확인한 390px 프리뷰는 두 그림 모두 핵심 의미 PASS. 원본 부재를 그림의 사실 오류로 판정한 것은 아니다.

## 확인 범위

- native view_image로 기존 `previews/I03-390.png`, `previews/I04-390.png`를 직접 열어 확인했다.
- 요청한 `content/attachments/palantir-apollo-operations-guide/figure-02.png`, `figure-03.png`는 현재 작업 디렉터리와 상위 quartz-garden 기준 모두 열기 실패(No such file or directory). quartz-garden 아래 해당 파일명 검색에서도 발견되지 않았다.
- 다른 파일 내용, 웹, 스킬은 읽지 않았다. 이미지를 생성하거나 수정하지 않았다.

## I03 — 프리뷰 PASS

- 제목 “Bundle 반입 ≠ 이미지 확보”가 390px에서 명확하다. Release 묶음의 “메타데이터” 표기와 아래의 별도 이미지 운송 그림이 분리되어 있다.
- 청록색 메타데이터 경로는 Source Hub → 운송 차량 → 중앙 검사 지점 → Target Hub 쪽 차량 → 내부 배포로 이어진다.
- 주황색 이미지 경로는 아티팩트 저장소 → 별도 이미지 운송 → 같은 중앙 검사 지점 → 로컬 이미지 저장소 → 내부 배포로 이어진다. 중앙 표기는 “검사·승인·전달”이며 두 경로 모두 이 지점을 통과한다.
- 경계 벽, 차량, 검사 지점으로 승인 반입을 표현한다. 벽을 우회하는 화살표나 실시간 cross-airgap 네트워크 연결은 보이지 않는다. 우측 배포로 향하는 주황색 꺾임도 승인 이후 내부 경로다.
- 하단 “누락된 이미지의 전달 책임은 조직에 남습니다”가 읽혀, Bundle만으로 이미지 확보까지 완료된다는 오해를 막는다.
- 잔여 문제: 390px에서 차량 내부 메타데이터 글씨와 경로 보조 문구는 매우 작다. 제목과 색상별 경로로 핵심 논지는 읽히므로 가독성 FAIL 사유는 아니다. 최종 원본과의 일치 여부는 확인 불가.

## I04 — 프리뷰 PASS

- 상단에 “관리 계층”, “아티팩트”, “구성·정책”, “업무 데이터”가 독립된 네 영역으로 놓이고, 각각 아래쪽 복구 화살표를 갖는다. 네 책임을 하나의 롤백 동작으로 합치지 않는다.
- 중앙 “소프트웨어 롤백 ≠ 데이터·업무 복구”가 390px에서도 가장 분명하게 읽힌다. 코드 롤백과 데이터/업무 복구의 비동일성을 명시한다.
- 하단 제목은 “격리된 시험 환경의 검증 제안”. v1 → 정상 v2 → 실패용 빌드 v3 → 이전 정상 버전 복구의 순서를 제안된 시험으로 묶는다. 실행 완료 체크나 성공 결과 표시는 없다.
- testbad-v3 / safeversion이라는 리터럴 대신 “실패용 빌드 v3” / “이전 정상 버전 복구”라는 의미상 대응 표기를 사용한다. 이 중립적 명칭 차이만으로 사실 오류로 판정하지 않는다.
- 하단 “설치 성공보다 실패·회수·복구의 증거”는 검증의 초점을 설명하며, 이미 성공적으로 실행했다는 보고 문구는 아니다.
- 잔여 문제: 390px에서 시험 상자 내부 문구와 네 복구 화살표의 작은 설명은 확대 없이 편하게 읽기 어렵다. 그러나 네 책임 구분, 롤백 비동일성, 격리 시험 제안이라는 핵심은 읽힌다. 상단 오브젝트 사이의 곡선에는 의미 설명이 없어 관계가 다소 모호하지만 복구 순서나 전체 복구 성공을 주장하는 명확한 화살표는 아니다. 최종 원본 확인은 남아 있다.

## 잔여 조치

최종 figure-02.png와 figure-03.png의 실제 경로 또는 파일을 제공받아 native view_image로 원본을 확인하고 프리뷰와 대조해야 전체 검토를 PASS로 닫을 수 있다. 현재 확인된 프리뷰만으로는 오해를 유발하는 워크플로 또는 읽히지 않는 핵심 논지를 발견하지 못했다.
