# 최종 이미지 세트 픽셀 리뷰

판정: **I01 PASS 유지 · I02 PASS · I03 PASS · I04 PASS**.

## 검토 범위와 정정

기존 review-I01-I02.md 및 review-I03-I04.md는 이전 검토 증거로만 읽었다. 이번에는 아래 I02·I03·I04의 정확한 전체 경로 원본 PNG 3장을 native view_image로 직접 열었다. I02의 390px 미리보기를 Pillow LANCZOS로 다시 저장하고 native view_image로 확인했다. 원본 생성·수정은 하지 않았다.

I03/I04의 종전 전체 FAIL은 잘못 축약한 파일명으로 원본을 열려다 실패한 검토 절차 오류였다. 기존 미리보기는 PASS였으며, 이번에 정확한 전체 파일명의 원본 확인을 마쳐 원본 검증 미완료 사유를 해소한다. 이미지 내용 오류를 수정한 것으로 기록하지 않는다.

## I01 — PASS 유지

파일: `content/attachments/palantir-apollo-operations-guide/palantir-apollo-operations-guide-infographic.png`

- 근거: 사용자 확인상 이전 최종 픽셀 검토 PASS 이후 변경 없음. 이번 회차에서는 다시 열지 않았다.
- 이전 관찰: 전체 운영 범위와 격리 환경의 별도 Hub, 승인된 Bundle 반입이 구분되어 있다. 상시 cross-airgap 연결로 표현되지 않았다.
- 잔여: 이전 390px 검토에서 보조 라벨은 작았다. 상세 독해에는 확대가 필요하다.

## I02 — PASS

파일: `content/attachments/palantir-apollo-operations-guide/palantir-apollo-operations-guide-figure-01.png`

- 원본에서 “최소 3개 노드 · x86_64”가 노란 라벨에 명시되어 있다. 이전 FAIL의 필수 표기 누락이 해소되었다.
- 세 노드를 하나의 중괄호로 묶고 “전체 권장 10 vCPU · 16GB”, “노드당 수치 아님 · 업무 자원 별도”를 함께 표시한다. 전체 권장량과 노드당 수치를 혼동하지 않는다.
- “Kubernetes Spoke 기준, 모든 엣지의 최소치가 아닙니다”라는 적용 범위 제한도 유지된다.
- 새 `previews/I02-390.png`는 390×260px이다. 제목, 전체 권장량, 노드당 아님 및 하단 핵심 명제는 식별된다. 최소 노드·아키텍처 라벨도 보이나 작다.
- 잔여: 390px의 최소 요건 라벨과 “Plan 조회 · 상태 보고” 등 보조 문구는 확대하여 읽는 것이 필요하다. 모든 작은 라벨의 모바일 가독성이 완벽하다고 판정하지 않는다.

## I03 — PASS

파일: `content/attachments/palantir-apollo-operations-guide/palantir-apollo-operations-guide-figure-02.png`

- 원본에서 “Bundle 반입 ≠ 이미지 확보”, “Release · 설정 · 메타데이터”와 별도 이미지 운송 경로를 확인했다.
- 청록색 메타데이터/Bundle 경로와 주황색 별도 이미지 경로 모두 중앙 경계의 “검사 · 승인 · 전달” 지점을 통과한다. 승인 절차를 우회하는 경계 통과 경로는 보이지 않는다.
- “접근 가능: 이미지 포함”과 “접근 불가: 이미지 별도 전달”이 구분된다. 승인 이후 로컬 이미지 저장소에서 내부 배포로 연결되며, 하단은 누락 이미지의 전달 책임이 조직에 남음을 명시한다.
- 잔여: 이전 390px PASS는 유지하되 이번에는 해당 미리보기를 재검토하지 않았다. 상자 내부 및 접근 조건의 보조 라벨은 모바일에서 확대가 필요하다.

## I04 — PASS

파일: `content/attachments/palantir-apollo-operations-guide/palantir-apollo-operations-guide-figure-03.png`

- 원본에서 관리 계층, 아티팩트, 구성·정책, 업무 데이터의 네 복구 책임과 각각의 독립된 아래 방향 복구 화살표를 확인했다.
- “소프트웨어 롤백 ≠ 데이터·업무 복구”가 중앙에 크게 명시되어 있다. 소프트웨어 롤백이 업무 데이터를 자동으로 되돌린다는 주장은 없다.
- 하단은 “격리된 시험 환경의 검증 제안”으로 명시된다. v1 → 정상 v2 → 시험용 결함 v3 → 안전한 버전 복구를 제안하며, 이미 시험을 실행하거나 성공했다는 결과 표시는 없다.
- 잔여: 상단 오브젝트 사이 곡선은 의미가 명시되지 않아 관계가 다소 모호하다. 다만 네 복구 책임을 하나의 자동 복구로 합친다는 명시적 표현은 없다. 이전 390px PASS는 유지하며, 시험 상자와 복구 보조 라벨의 상세 독해에는 확대가 필요하다. 이번에는 해당 미리보기를 재검토하지 않았다.

## 파일 무결성

동일 디렉터리의 image-manifest.json에 실제 최종 원본 PNG 4개의 SHA256, 바이트 수, 가로·세로 픽셀을 파일에서 계산해 기록했다. 미리보기는 원본 4개 매니페스트에 포함하지 않는다.

## 3줄 요약

I01은 변경 없는 이전 PASS를 유지하고, I02는 최소 3개 노드·x86_64 및 전체 권장 자원 표현을 직접 확인해 PASS다.
I03/I04는 정확한 전체 파일명의 원본 픽셀 검토로 종전 경로 오류를 정정하고 PASS로 닫았다.
원본 4개 무결성 정보를 기록했으며, 모바일 보조 라벨은 확대가 필요하다.
